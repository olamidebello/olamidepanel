# Legal notices and operator review

The site includes `/terms`, `/privacy` and `/copyright`, with version `2026-10-15`. Login requires an explicit `accept_terms: true` boolean; an unchecked checkbox supplies this in the GUI. Successful confirmed login records user ID, version and the latest acceptance timestamp for that version in `legal_acceptances`. This records agreement to the Terms and acknowledgment of the Privacy Notice; it is not marketing consent. Account deletion cascades to this table, so records do not survive user deletion. No IP/device evidence or full per-login acceptance history is recorded. Bump both the backend TERMS_VERSION and the page version when publishing changed terms.

The privacy text describes actual shipped behavior, including local storage, session cookies, hashed passwords, role access, server-side logging, retained files and operator-managed backups. Reference used: FTC Consumer Privacy guidance, https://www.ftc.gov/business-guidance/privacy-security/consumer-privacy. That guidance emphasizes clear and accurate descriptions of data practices. It does not certify this notice's compliance.

Before public/commercial use, the operator should review these drafts with qualified counsel and provide the correct contracting/operator legal entity, mailing/contact details, hosting/subprocessor identities, processing locations, retention schedules, applicable legal bases and any jurisdiction-specific rights/processes. Confirm ownership and licensing of original material and preserve third-party notices. No governing-law choice, arbitration provision, billing/refund policy or statutory copyright-agent designation has been invented. The copyright notice is not a new open-source license and does not replace dependency licenses.

These additions do not implement privacy request fulfillment, automatic deletion schedules, a cookie preference center, third-party licensing or a complete acceptance audit system. The current notices must be revised if deployment practices or integrations change.

Deployment uses the existing playbook. Restart initializes the additive MySQL legal_acceptances table; no existing account data is rewritten. Back up the database before update. Existing authenticated sessions are not forced out by this change; they will see confirmation on their next login. API clients must explicitly add accept_terms=true as a JSON boolean at login.
